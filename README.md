# Как пользоваться

## Конвертировать md в html

- Скопировать md-файл в директорию `pandoc stuff`.
  - Если в файле есть картинки, то папку `img` положить рядом с файлом.
- Через консоль зайти в pandoc stuff и выполнить команду:

```
pandoc "source.md" -o "index.html" --template="fmptemplate.html" --syntax-highlighting=fmp.theme
```

- Получившийся html-файл (с папкой img, если она есть) перенести в директорию `content`, создав там нужные подпапки.
- Добавить в `index.html` ссылку на статью.
  - Ссылка должна выглядеть вот так, с завершающим слэшем:

```html
<a href="/imnotafreid/content/foobar/">Foobar</a>
```



## Как это все устроено

- `/pandoc stuff`
  - `fmp.theme` - "тема" для оформления исходного кода.
    - Обычный json, можно нейросеткой сгенерировать любой внешний вид по вкусу.
  - `fmptemplate.html` - шаблон, в который пандок вставляет контент из md.
    - Обычный шаблон пандока, но в него внедрены
      - кнопка "Наверх" и "Домой"
      - css-стили для статьи \ оглавления \ всего остального
      - скрипт фолда \ анфолда исходного кода
      - скрипт, формирующий оглавление из заголовков
    - В случае если надо приделать новые скрипты, их надо сложить в папку `/scripts` и явно вписать в этот шаблон. Аналогично со стилями - класть в папку `/styles` и приделывать в шаблоне. Добавлять в это место:

```html
<!-- ============= ============= Мои стили и скрипты ============= ============= -->
<!-- Должны подключать тут, чтобы перекрыть дефолты пандока -->
<link rel="stylesheet" href="/papyrus/styles/article-page.css">
<script src="/papyrus/scripts/oglavlenie.js" defer></script>
<script src="/papyrus/scripts/source-code-expand-collapse.js" defer></script>
<!-- ============= ============= =================== ============= ============= -->
```

- `/styles`
  - `article-page.css` - стили для статьи. Здесь собраны все стили - для текста, кнопок, меню оглавления и все остальное, все что есть на странице статьи.
  - `main-page.css` - стили для главной страницы, на которой собраны ссылки на все статьи.



# Проблемы

## Пути github pages vs локальные пути

- Для github pages рут это `https://fullmetalprogrammist.github.io/` но все ссылки дополняются названием репозитория `papyrus`.
  - Поэтому для ghp ссылки надо оформлять как `/papyrus` для статей, стилей, скриптов и т.д.
  - Но локально на компьютере это вызывает проблемы, потому что рутом будет просто папка, из которой запускаешь сервер, например через расширение live server для vs code, безо всяких /papyrus.
  - Так что я сгенерировал мини-веб-сервер, чтобы эту проблему обойти. Он находится в корне, файл `server.js` и запускается вот так:

```
node server.js -b imnotafreid
```

- Тогда локально пути можно будет писать так как же как и для ghp.
- Есть live reload.
- Страница будет доступна по адресу:

```
 http://localhost:3000/imnotafreid/
```
